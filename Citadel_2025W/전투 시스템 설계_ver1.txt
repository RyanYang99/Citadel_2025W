전투 시스템 설계

1) 목표 
-메인 맵에서 잠겨있는 여역 (미오픈 타일 / 구역 ) 클릭 -> 전투 진입 ( 전투 Scene으로 이동)
- 전투는 자동 전투를 한다. (스킬/ 수동 컨트롤 없음)
- 적을 일정 수 ( 라운드 Kill 목표치) 처치하면 승리 
- 승리 시 해당 구역이 Open( 영토 확장)

2) 씬 구조
MainScene -> 유저 건설 , 인벤토리, 배럭 레벨 등을 관리하여 그 데이터만 BattleScene으로 넘긴다.

BattleScene 전투 전용
-상단 ( 적 진영 ) / 하단 ( 유저 진영)
-유닛 자동 스폰 + 자동 전투 + 승패 판정 수행
-결과(BattleResult) 만 MainScene으로 넘긴다.
 ** 배틀씬은 메인씬의 오브젝트나 컴포넌트를 직접 참조하여 넘기지 말 것 . 
Inventory/buildingManager/Place 등 . 


3) 메인 -> 전투 데이터 전달 
-전투 시작에 필요한 최소 데이터만 포함하는 스냅샷 객체를 만들 것
- 필드 예시
Zone -> 어떤 지역/ 타일인지 식별
StageId : 전투 난이도 레벨
PlayerBarracksLevel : 배럭 레벨 -> 스폰 속도/ 최대 유닛 / 스탯 에 사용

전투 -> 메인 
ZoneId, StageId, Victory/loose (bool 형으로 ) /
승리시 -> 해당 구역 Open 처리 + 저장 반영 (SaveLoadManager)나 타일 쪽에 데이터 전달
패배시 변화 없거나 패널티 ( 병력 감소 ? )

4) 전투 진행 방식 
-전투 시작 시 양쪽이 일정 주기로 유닛을 자동 소환
-유닛은 가까운 적을 자동 공격
- 공격/이동/사망 처리 자동 진행
- 적 처치 수 == 목표 치 에 달성시 승리

5) 난이도 설계
-스테이지 프리셋으로 관리
- BattleStageData(예) Object를 넣어서 레벨별로 하나씩 생성해서 데이터를 조절
-Stage Data -> StageId, TargetKills 
-Player -> SpawnInterval , MaxSpawn( 최대로 필드에 있을 수 있는 수 ) , HP/Damage 배수
-Enemy -> SpawnInterval (레벨 별로 다르게 ) , MaxSpawn( 레벨 올라 갈수록 많이 ) , HP/Damage 배수 , 유닛 확률 ( 궁수/. 보병/ 방패병)
**레벨 별 난이도 , 1 => 적 스폰 느림 + 적 적음 , 스탯 낫음 , 2=> 스폰 빠름 , 적 증가 , HP 증가
3=> 방패병 비율 증가 / 궁수 비율 증가 등 조합 강화

6) 전투 시스셈 구성 ( 역할 분리) 
1.BattleManager  (전투 흐름 / 승패 판정 )
->Request ( 배틀 요청 받기 )
->StageData
->전투 시작/종료 상태 관리
->killCount 집계/관리 ( == Targetkill 이면 승리)
->Battle결과 생성후  -> MainScene으로 복귀 처리 ( 여기서 데이터를 넘김)

2. Spawn 관리자 ( 랜덤 스폰)
-> Stage기반으로 양쪽 스폰 타이머를 활용할 것
-> 확률 테이블 기반으로 유닛 타입 결정
-> SpawnSystem 

3. SpawnSystem / unitFactory ( 실제 생성 담당)
-> 프리팹 
-> 팀 / 배치 스폰 포인트
-> 최대 동시 유닛 수 제한 관리
-> 런타임 초기화 ( 유닛 생성 관련하여 )

4. UnitRuntime( 유닛 AI 전투)
-> 유닛 마다 붙는 스크립트 
-> 타겟 탐색 : 가장 가까운적 ( 다양하게 할거면 , 조건 ( 궁수병은 멀리있는적 먼저  등)
-> 이동 : 거리가 멀 경우 이동
-> 공격 : 쿨타임 마다 공격 ( 원거리/ 근접 다르게 조정할것)
-> Hp ==0 되면 사망 이벤트 
전투 규칙은 최대한 UnitRuntime 내부에서 개별행동으로 처리 해서 할 것
승패/킬 집계는 BattleManager가 담당 

7) 유닛 종류 
- 궁병 ( 원거리 ) : 공격력 높음, 체력 낮음
- 보병 ( 근접) : 공격력 ,체력 보통
- 방패병 ( 근접)  : 공격력 낮음 ,. 체력 높음
 ** 유닛 데이터, Type , Prefab , Hp, Damage,Range,MoveSpd, AttackInterval

8) 애니메이션 / Vfx는 나눙에 붙여도 되도록 분리 작업
-> 캡슐 . 큐브 프리팹으로 전투 완성 ( 스폰/이동/공격/ 사망)
-> UI 킬 카운트 . 목표치 
-> 스테이지 밸런싱
-> 마지막에 3D 모델. 애니. 이펙트 연결 ( 애니메이션 미완성이어도 전투 로직은 테스트 가능하도록)

9) 메인씬과의 연동 (최소로)
-> StageID, ZoneId, PlayerBarracksLevel  , 해당 Zone -> 언락 후 True 저장 , 보상(선택, 가능하면 )

10) 전투씬은 MainScene 시스템 참조 하지 말 것
-> Inventoryh 직접 접근 X
-> BuilidngManager 직접 접근 X
-> Request/Result로만 데이터 이동
-> 하드코딩 최소화 -> StageData로 조정
-> 스폰/전투/결과 로직 분리 유지 할 것
